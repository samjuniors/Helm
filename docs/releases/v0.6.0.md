# Helm v0.6.0 — Existing Projects, Regression Guards and Guided Planning

**Released:** November 3, 2026
**Compatibility:** Node.js 18+, Git, MCP-capable assistants for integrated use
**Version:** 0.6.0 (includes the capabilities developed in 0.5.0, which was not published separately)

## What's new

### Adopt existing software safely
- Bring a new, partially built, or established Git project into Helm on a dedicated `kit/integration` branch.
- Adoption refuses uncommitted changes and preserves existing application source files.
- Generate an inspectable `docs/STATE.md` containing detected parts, roadmap progress, and open decisions.

### Scan and understand your project
- Read-only `kit_scan` identifies project maturity, major files, test entry points, and likely frontend, backend, data, mobile, desktop, or library parts.
- Findings distinguish verified observations from inferences.

### Track regressions with evidence
- `kit_guard` records baseline checks and compares follow-up results, including separate checks for monorepo parts.
- Full, partial, missing, and pre-existing failing checks are reported separately. A partial result does not mean all work is verified.
- The guard runs detected or configured test/build commands. Review them first, as some project commands can modify files.

### Get structured decisions and plans
- `kit_consult` structures interviews, evidence grading, option comparisons, recommendations, and bounded refinement rounds.
- Human approval is required before a proposal becomes roadmap work by default; AI tools cannot record that approval.
- Add or refresh Helm's project rules in AGENTS.md without replacing unrelated instructions.

### Tooling
- Five new MCP tools: `kit_scan`, `kit_guard`, `kit_consult`, `kit_state`, and `kit_adopt`.
- **14 total MCP tools**.
- New slash commands and updated skill guidance for the additional workflows.

## Preserved compatibility
- Maintains the `@samjuniors/helm` package and `helm` CLI identity and MIT licensing.
- Preserves `.agents/product-kit/` project data, existing milestones, approvals and progress records.
- Keeps the Helm v0.4.1 Git-safety behavior: initializing in a dirty Git repository does not commit unrelated user work.
- Retains backups, guarded project upgrades and checksum verification for release downloads.

## Upgrade

Download and extract the ZIP into a separate folder; from the **new** extracted Helm directory run:

~~~sh
node update.mjs --into /path/to/existing/helm --dry-run
node update.mjs --into /path/to/existing/helm
~~~

Restart your MCP clients to load the updated server. No automatic project engine replacement is required; existing generated projects retain their engine and state unless you explicitly choose a compatible upgrade.

## Verification and limitations

Reconciled source was tested locally on Windows with Node.js 24: 91/91 v0.6.0 feature checks, 46/46 MCP SDK integration checks, plus existing Helm init safety, update, version metadata, rename, and compatibility tests. Archive integrity and installation checks were performed on the released source.

Hosted GitHub Actions is subject to a repository billing/runner limitation; CI was not counted as passing without jobs actually running. Live Claude/Codex/Antigravity production hosts, macOS/Linux and all detected language toolchains were not independently verified in this release.

**Security:** External agents and user-defined check commands run with your local account permissions. A Git worktree is not a security sandbox. Review agent configuration and use approval mode for sensitive projects.
