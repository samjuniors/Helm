# Helm v0.7.0 — Easier Installation and Maintenance

**Release date:** November 3, 2026
**Compatibility:** Node.js 18+, Git, Windows/macOS/Linux (live setup validation completed on Windows)

## What's new

Helm v0.7.0 introduces a single setup assistant for installing, updating, removing, and checking Helm:

- `setup.cmd` — Windows double-click setup menu.
- `setup.sh` — Unix shell entry point.
- `setup.mjs` — CLI for `install`, `update`, `uninstall`, and `status`.

The managed installer copies Helm into your home directory, checks that the MCP server starts correctly, and registers Claude Code or Codex where available. It creates a launcher in `.helm/bin`; you choose whether to add that folder to PATH.

## Upgrades and safety

- Run `node setup.mjs update` from the newly extracted version. The previous installed copy is backed up, the MCP server is tested again, and existing project data is left untouched.
- Setup will not overwrite an unrecorded installation, a source repository, or an unrelated launcher without intervention.
- Uninstall asks for confirmation and removes only Helm's recognized managed installation. It does not delete your projects, Git history, or unrelated files under your home directory. `--purge` removes recognized Helm update backups.
- Existing source-clone installations can keep using `git pull --ff-only` and `node install.mjs`; no mandatory migration is required.

## Upgrading from v0.6.0

Download the new `helm-v0.7.0.zip` and extract it to a **separate folder**. If you have an installation created using the new setup assistant, run:

```sh
node setup.mjs update --dry-run
node setup.mjs update
```

For older installations without a setup record, continue using the legacy updater from the newer release:

```sh
node update.mjs --into /path/to/old/Helm --dry-run
node update.mjs --into /path/to/old/Helm
```

For a Git checkout, use Git rather than replacing source files with an extracted release. Always make a backup before upgrades.

## Preserved features

The v0.6.0 project scanning, regression guards, consultation, adoption, agent orchestration and 14 MCP tools remain unchanged. Helm retains the `@samjuniors/helm` package identity and MIT license.

## Verification

On Windows with Node.js 24, the isolated setup suite passed 15/15 checks, the existing Helm feature suite passed 91/91, the MCP SDK integration suite passed 46/46, and previous init-safety, upgrade, release and rename regressions passed. The POSIX-specific setup tests and live external Claude/Codex/Antigravity host apps were not executed in this release. Hosted GitHub Actions may be unavailable because of the repository's payment/runner status; no unexecuted hosted tests are claimed as passing.

## Notes

A Git worktree is not a security sandbox. External agents and configured tests run with your local user privileges. Project-generated files in `.agents/product-kit/` are preserved.
