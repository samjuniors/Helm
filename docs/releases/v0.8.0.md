# Helm v0.8.0 — Built-in, Verified Updates

**Release:** v0.8.0 (new feature; no project-state migration)
**Compatibility:** Node.js 18+, Git and an MCP-compatible client for integrated use

## What's new

A **managed Helm installation** can now update directly from GitHub Releases:

```sh
helm update --check
helm update --dry-run
helm update
```

- `--check` queries the latest stable published release and compares it with the installed version, with **no file changes or archive downloads**.
- `--dry-run` explains the proposed update and safety steps without changing installed files or downloading a release archive.
- `helm update` downloads the official versioned TGZ and `SHA256SUMS`, verifies SHA-256, stages and validates the archive, and then runs Helm's existing backup-and-rollback updater and MCP startup verification. Restart your coding assistant afterwards.
- The registered MCP server path, custom project files, project decisions, Git history, and existing user work remain unchanged.

## Installation compatibility

**Important one-time transition:** If you currently use v0.7.1 or earlier, you must upgrade to v0.8.0 **once** via the normal [ZIP update process](https://github.com/samjuniors/Helm/blob/main/docs/UPGRADING.md). Once running v0.8.0, managed installations can use `helm update` for future versions.

- The updater supports **setup-managed installs** with an authentic `.helm/install.json` record.
- A source checkout containing `.git` cannot self-update; use `git pull --ff-only` and review your changes.
- A manually extracted ZIP without a setup record continues to use `node update.mjs --into OLD-INSTALL`.
- Previewing, checking and updating cannot rewrite a Git repository, modify project kits, or silently replace an unrelated installation.
- No new MCP tools: Helm continues to expose **14 tools**.

## Security and rollback

Updates are restricted to official GitHub Release URLs. Both file names and release versions are validated. The downloaded TGZ is checked against `SHA256SUMS` before extraction. The extractor limits archive size and count, rejects absolute/escaping paths, duplicate names and links, and never extracts into an existing project.

The existing updater preserves a backup and checks MCP startup; if the updater fails, it attempts to restore the previous files. Review the error and backup before retrying. A checksum mismatch, missing release asset, unsafe archive, malformed state record, same version or attempted downgrade leaves the managed installation unchanged.

## Downloads

- `helm-v0.8.0.zip` — full distribution, manual install or one-time upgrade.
- `helm-v0.8.0.tgz` — npm-compatible archive, not published to the npm registry.
- `SHA256SUMS` — SHA-256 hashes for both archives.

## Verification and limitations

The feature includes isolated offline regression tests for latest-version checks, preview, checksum failures, archive traversal/links, missing or tampered install records, Git clone refusal and a full managed-update simulation. Cross-platform GitHub Actions results, actual packaged-archive checks and any unverified external client hosts are reported on [PR #14](https://github.com/samjuniors/Helm/pull/14) and the GitHub Release.

Helm uses the GitHub Releases API at update time. A network connection is required for the check/update commands. A working release URL and SHA-256 checksum protect downloaded bits but do not grant the external agent permission to access your private projects; helper agents retain local account permissions.
