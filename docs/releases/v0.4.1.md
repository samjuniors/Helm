# Helm v0.4.1 — Maintenance and compatibility

[Official GitHub Release](https://github.com/samjuniors/Helm/releases/tag/v0.4.1)

This historical record summarizes the release's originally published notes.

## Improvements

- Added optional read-only repository health checks through `npm run audit:repo`.
- Corrected same-name rename behavior so `rename.mjs --name helm` records the expected plugin marker.
- Improved package metadata, keywords, and protection against accidental npm registry publication.
- Added regression tests for existing Helm v0.4.0 upgrades and repeat upgrade/rename operations.

## Compatibility

The release preserves Helm's CLI, MCP server identity, project orchestration engine, `.agents/product-kit/` project state, MIT license, and existing release tooling. No intentional breaking changes were recorded.

## Downloads and installation

The official release contains `helm-v0.4.1.zip`, `helm-v0.4.1.tgz`, and `SHA256SUMS`. Requirements: Node.js 18+, Git, and an MCP-capable assistant for integration.

For older ZIP copies, preview using the updater in the **new** extracted release before applying:

~~~sh
node update.mjs --into /path/to/existing/helm --dry-run
node update.mjs --into /path/to/existing/helm
~~~

See [Upgrading](../UPGRADING.md) for current guidance.

## Historical archive size

The original published v0.4.1 ZIP was re-inspected on November 3, 2026. It contains **3,656 files under the development-test dependency directory** (inside `tests/node_modules`) and has 3,715 file entries in total. This is not needed for a typical end-user installation and makes the historical archive larger than newer releases. The v0.4.1 archive and tag remain unchanged for reproducibility; new users should prefer the latest published version. This finding does not establish that the archive contains malicious files.

## Verification status at publication

The release notes report local updater, initialization safety, metadata, rename and packaging checks. They state that hosted GitHub Actions cross-platform testing had not executed at that time. These notes do not claim an unexecuted test passed.
