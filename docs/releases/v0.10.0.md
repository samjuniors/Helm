# Helm v0.10.0 — Guided Installer and Advanced Setup

**Change type:** MINOR — setup and integration experience improvements from v0.9.1.
**Requirements:** Node.js 18+, Git for Git-backed Helm project workflows.

## What’s new

- A **guided terminal installer** from `helm setup`, `node setup.mjs`, or a first-time verified interactive bootstrap. The wizard displays read-only client detection, supports picking available Claude Code and Codex CLI integrations, a safe installation destination, and Windows user PATH opt-in, followed by a detailed dry-run preview and explicit approval.
- **A better existing-install workflow:** add a supported client later without replacing a recorded managed installation or an existing MCP registration. An unrecognized registration with Helm's name is refused instead of overwritten.
- **Advanced use:** retain explicit commands such as `helm install --host codex --dir /absolute/path --dry-run`, `helm install --host none` (CLI only), `helm update --check`, `helm uninstall --dry-run`, and add read-only `helm doctor --json`.
- **Update detection:** guided setup checks the latest published stable GitHub Release and shows when a newer version is available. Download and install happen only after a separate approved update; offline environments can continue using Helm.
- **Clear environment status:** distinguish supported automatic CLI registration from manually guided IDE/desktop configurations such as Antigravity, Claude Desktop, Cursor and VS Code. No unverified GUI or IDE integration is claimed as connected.
- Existing 14 MCP tools, source/project history, backups and install state remain compatible.

## First-time installation

With a reviewed version-pinned bootstrap script (Windows PowerShell or macOS/Linux), the installer opens a wizard when a terminal is interactive. Read and inspect the bootstrap script before running it; see the [installation guide](https://github.com/samjuniors/Helm/blob/main/docs/INSTALLATION.md).

If you prefer scripting, use an explicit host option. For example:

```powershell
node .\setup.mjs install --host codex --dry-run
node .\setup.mjs install --host codex
```

Or, for an already managed install:

```sh
helm setup
helm doctor --json
helm update --check
```

## Installation safety

- No automatic client registration based solely on a detected application folder; an explicit user selection and approval is required in the wizard.
- Existing managed copies are retained during reconfiguration. Foreign/unrecognized MCP registrations are never silently removed.
- Custom installation locations are supported through `--dir`. By design, the uninstaller retains custom folders for manual review rather than deleting them automatically.
- Antigravity, Claude Desktop, Cursor and VS Code appear in detection with **manual setup instructions** pending separate tested integration adapters. Codex CLI/IDE share configuration; Claude Desktop is not equivalent to Claude Code.
- Release lookup is read-only; Git source clones remain Git-managed. Project source, existing project state and Git history are preserved.

## Quality gates

Cross-platform CI and artifact verification results are linked from the release and PR. Fake client environments are used for installer lifecycle tests; automated tests do not prove third-party GUI session behavior. No separate desktop GUI installer is shipped in this release.
