# Helm v0.11.0 — Local Releases and Environment Reliability

**Change type:** MINOR (new release command, safer project-level MCP integration and automatic PATH repair).
**Requirements:** Node.js 18+, npm; Git for project management and release publishing; optional \`gh\` only for publication.

## What's new

- \`helm release\` builds a versioned ZIP, npm-compatible TGZ and SHA256SUMS after local metadata, regression and MCP integration checks; \`helm release --publish --yes\` publishes with GitHub CLI, no GitHub Actions runner or paid CI required.
- ZIP packaging no longer needs the external \`zip\` command on Windows.
- \`helm doctor --repair --dry-run\` previews launcher/PATH repairs; \`--yes\` performs Helm-owned changes with no third-party credential edits. Windows user PATH and Bash/Zsh/Fish startup profiles are supported.
- Project-only \`helm connect\`/\`helm disconnect\`, including \`helm install --scope project\` aliases, add/remove MCP settings in a selected project for Claude Code and Codex without editing global registrations.
- Existing third-party MCP configurations and custom shell profiles are preserved; write operations retain backups. MCP uses the absolute Node path to avoid differences between terminal and IDE PATH.
- Guided setup offers persistent PATH and a repair choice.

## Compatibility and safety

No migration of \`.agents/product-kit/\` or Helm's MCP tool names. Existing user/global setup records remain compatible. Existing custom project registrations are never force-replaced; conflicts require human review. Codex project-local settings load only in trusted projects. Separate IDE/desktop integration for Antigravity, Claude Desktop, VS Code and Cursor remains guided/manual rather than claimed as tested.

Helm cannot automatically fix a missing account token or arbitrary client-owned environment variables. Set provider credentials securely through the provider's documented method.

## Verification

New unit acceptance covers project install/repeat/uninstall/conflict handling, POSIX profile repair, cross-platform ZIP integrity and local release approval guards. Run \`npm test\`, \`npm run test:integration\`, \`npm run pack:release\`, plus Windows/Linux GitHub CI when available. Cross-host desktop GUI behavior remains outside automated fixtures; no unexecuted real-host test is claimed to pass.
