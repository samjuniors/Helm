# Helm v0.11.0 — Reliable Environment Repair and Manual Releases

**Release type:** MINOR — additional environment and release-management capabilities, built on the guided setup released in the unreleased v0.10.0 source baseline.

## Key changes

- `helm repair --dry-run` previews recovery; `helm repair --yes` restores a Helm-owned launcher, user PATH entry and only clearly identified managed configuration. On Windows, this is an idempotent **current-user** registry PATH update. On macOS and Linux, only Helm-marked shell-profile lines are created or removed; no system PATH or unrelated entries are touched. Existing terminal and IDE sessions may need restarting.
- Installations use an **absolute Node executable** in launcher scripts and MCP client configuration so a desktop assistant does not depend on inheriting the terminal's Node PATH.
- Global `--scope user` registration stays separate from `--scope project --project FOLDER`. Codex project registration uses only a marked local `.codex/config.toml` block; Claude Code registration runs in the saved project folder. Uninstall removes only Helm-owned registrations and does not delete project files.
- `helm release --dry-run` and `helm release --yes` publish from a reviewed, clean `main` Git checkout without GitHub Actions. The command requires full metadata checks, regression and MCP integration tests, a repository audit, SHA-256 verification, matching remote commit and an authenticated GitHub CLI before tagging and uploading versioned assets. Existing tags/releases are never overwritten.
- Node-only ZIP32 STORE packaging removes the external `zip` dependency and includes dotfiles. TGZ remains the `npm pack` format.
- The guided setup now accepts terminal EOF as a normal exit rather than a crash in a Linux pseudo-terminal. New tests cover profile/registration ownership, ZIP packaging and preview paths.

## Installation and maintenance

Use the version-pinned installer described in [Installation](../INSTALLATION.md), or download `helm-v0.11.0.zip`, `helm-v0.11.0.tgz` and `SHA256SUMS` from the official GitHub Release **once published**. Downloads are private until GitHub repository access is granted.

```sh
helm doctor --json
helm repair --dry-run
helm repair --yes
helm install --scope project --project /path/to/app --host codex
helm release --dry-run
```

Uninstall remains `helm uninstall --dry-run` then `helm uninstall --yes`, with Helm-managed PATH entries and client registrations removed only if recognized.

## Compatibility and limitations

Node.js 18+, Git for project/release workflows. The manual release command requires npm, the `gh` CLI, network/authentication and a reviewed clean local `main` checkout. Test dependencies must be installable for the MCP integration gate. Automatic environment repair cannot fix missing Node.js, an unavailable operating-system profile, third-party IDE permissions, unknown client config formats, or all inherited environment variables. `helm doctor` remains the read-only diagnostic command; all writes require an explicit install/update/uninstall or `repair --yes` action.

Existing kit state under `.agents/product-kit/` and all Git history remain unchanged. A managed installation never silently switches registration scope. Antigravity, Claude Desktop, Cursor and VS Code still require manually verified integration; no untested automatic registration is claimed.
